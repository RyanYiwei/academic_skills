# 笔记格式规范

## 总原则

- **输出语言**：中文为句子骨架，英文技术术语按下方「语言与翻译策略」直接嵌入，不做逐词翻译
- **数学公式**：行内公式用 `$公式$`，独立公式块用 `$$公式$$`；原始材料若使用 `\[ \]` / `\( \)`，一律改写为 `$$ $$` / `$ $`
- **格式**：标准 Obsidian Markdown，无 emoji，不用 `——`（中文语境用逗号、冒号、分号或句号代替）
- **内容**：详细但不冗长；不重复解释已出现的概念；不拓展原材料之外的内容

---

## 语言与翻译策略

笔记的目标读者英语水平大致相当于雅思 6 分：日常学术英语没问题，但生僻词汇、不常见搭配可能看不懂。写作时把中文当句子骨架，英文术语和惯用表达直接嵌入其中，不做逐词对照翻译，读起来应该像双语使用者自然写笔记的样子。

### 三种情况，分别处理

**1. 常见 ML/CS 术语与基础英文词汇——不翻译。**
这类词本身构词简单，且在技术语境里几乎总是直接说英文，加中文反而生硬。例如：gradient descent、loss、batch、epoch、embedding、attention、softmax、dropout、learning rate、encoder/decoder、token、checkpoint、fine-tuning、residual connection。这类词全篇直接用英文，不加括号翻译。

**2. 生僻或超出雅思 6 分范围的英文单词——翻译一次即可，不重复标注。**
有些词本身不是 ML 专属概念，但单词生僻（如 saturate/saturation、degenerate、asymptotic、monotonic、orthogonal、equivariance、curvature），第一次出现时给一个简短括号翻译：`saturation（饱和）`。**全篇只需要翻译这一次**，之后再出现直接用英文，不用每次都重复标注。

**3. 材料专属的新概念——用一句话解释，而不是贴翻译。**
对于材料里第一次定义、且是核心内容的概念（模型特有的组件、新提出的机制等），第一次出现时用一句直觉性说明代替翻译，帮读者理解"这是什么"，而不只是告诉它对应的中文词：

> "RNN 的核心是一个不断更新的 **hidden state** $h_t$，可以理解为模型对"截至当前已经看到的所有输入"的一个 learned summary。"
>
> "Query：我正在寻找什么。Key：每条数据用什么特征参与匹配。Value：匹配成功后希望取回什么信息。"

### 判断标准

- 词本身简单、且是技术语境里的惯用说法 → 不翻译（第 1 类）
- 词本身生僻但概念不难、翻译一下就懂 → 括号翻译一次，之后不再重复（第 2 类）
- 概念本身是材料重点，需要理解含义而不只是认字 → 用一句话说明，而不是翻译（第 3 类）
- 论文标题、模型/架构专名（Transformer、ResNet、LSTM、Mamba 等）永远不翻译，也不需要额外解释

### 标题

标题中英文混排与否取决于哪种更符合该领域的实际叫法，不强制每个标题都要中英对照。`## Scaled Dot-Product Attention` 这种纯英文标题完全可以，不必写成 `## Scaled Dot-Product Attention（缩放点积注意力）`。

## 数学公式规范

- 行内公式：`$f(x) = ax + b$`；独立公式块：`$$ ... $$`
- 原始材料的公式若写成 `\[ ... \]` 或 `\( ... \)`，一律转换为 `$$ ... $$` / `$ ... $`，这是最常见的格式错误来源
- 逻辑上相关的多个表达式尽量写进同一个 `$$...$$` 块（用 `\qquad` 或逗号分隔），不要拆成连续多个只有一行内容、中间夹着空行的独立公式块
- 公式后紧接一句话说明变量含义，不必每个变量单独起一行，除非变量数量较多（4 个以上）或含义复杂
- 向量、矩阵使用 `\mathbf{}` 或 `\boldsymbol{}`；文字下标用 `\text{}`（如 `W_{\text{att}}`），不用 `\mathrm{}`
- 推导过程只保留关键步骤，省略纯机械运算

## 跨笔记复用与链接

当目标笔记所在目录下**已有其他相关笔记**时（例如同一课程/同一领域的系列笔记），生成前先读 2-3 篇作为参照，并遵循：

1. **风格对齐**：标题层级、公式记法、表格样式、callout 用法、结尾板块（如「相关笔记」「参考文献」）都跟着已有笔记的约定走，不要另起一套格式。
2. **查重**：若新材料中的内容与已有笔记重复（同一个概念、同一条公式的推导），**从新笔记里删掉**，改成到该概念首次出现处的链接引用。
3. **反向补充**：若新材料里的某段内容其实更适合放进某篇已有笔记（例如一个具体例子补充了那篇笔记里一条笼统的结论），把它**补充进那篇旧笔记**，旧笔记只增不减，不要为了保留内容而在新笔记里重复写一遍。
4. **链接写法**：把链接直接嵌在正文关键词上，尽量不要写成"参见 `[[Note]]`"这种挂在句尾的括注。

   ```markdown
   ❌ decoder 需要一个初始 hidden state（详见 [[RNN#若干实现细节]]）。
   ✅ decoder 需要设置初始 hidden state，做法与 [[RNN#若干实现细节|RNN 中 initial hidden state 的几种选择]] 相同。
   ```

若目录下没有其他笔记（单篇独立笔记场景），跳过这一节，直接用下方默认模板。

## 内容组织原则

1. 严格按原材料的逻辑顺序组织，不重排结构
2. 定义类内容：**加粗核心词**，后接解释
3. 列表项不超过 6 项；超过时按语义分组，各组加小标题
4. 对抽象概念可用一句直觉性说明辅助理解，但须简短（一句话以内）
5. 图表若无法还原，用文字描述其含义和结论
6. **材料是课堂 transcript 时**：去掉"课堂问题：""同学问：""讲师提到"之类的转述外壳，把口语化的一问一答直接改写成陈述句；只保留有实质技术内容的问答，删除行政性/无信息量的片段（寒暄、重复、跑题）
7. 若某个概念在同一篇笔记的不同小节都会用到，只在首次出现处完整解释，后文用 `[[#标题|锚文本]]` 站内链接回指，不要重复展开

## 收尾结构（可选）

若同目录下的其他笔记有固定的收尾板块（常见的是「相关笔记」列出本笔记依赖/关联的其他笔记及一句话说明，「参考文献」列出原始论文或课程出处），新笔记也应加上，保持风格统一；若其他笔记没有这类板块，则不必额外添加。

---

## 禁止事项

- 禁止使用 emoji
- 禁止逐词翻译已经借词化的通用术语（见「语言与翻译策略」）
- 禁止使用 `——`；需要语气停顿或补充说明时用逗号、冒号、分号或句号
- 禁止重复解释已解释过的概念（同篇笔记内，或已在同目录其他笔记中出现）
- 禁止在原材料范围外进行大量拓展
- 禁止生成冗长的引言段落或总结段落
- 禁止在笔记前后附加"以下是整理好的笔记"之类的说明语
