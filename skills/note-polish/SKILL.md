# Note Polish：笔记排版优化

用户的笔记大多是从教材整理来的复习材料，内容已经核对过。所以这个 skill 的价值在于**只让它显示得更好**：文字、符号、公式项、编号和链接一个都不能变。改一个下标或漏一项，都可能让用户把错的东西背下去，而且很难被发现。

## 原则：只动排版，不动内容

- **公式拆分后必须逐项等价**：项的顺序、符号、`\underbrace` 标签、`\tag` 编号都保持原样。能新增的只有：`aligned`/`gathered` 环境、`&`、`\\`、`\quad`/`\qquad` 缩进、`{}` 这类占位。
- 不改正文文字、不改链接、不改 callout 类型和折叠状态（`[!note]-` 里的 `-`）、不改 frontmatter。
- 唯一允许删除的内容是用户留下的排版标记行（见下文）。
- 如果在过程中看到**内容**问题（公式写错、链接失效、编号对不上），只在最后的报告里提出来，不要顺手改。用户需要知道改了哪些地方，混进来的内容修改会让他们没法放心地只看排版 diff。

## 工作流

### 1. 确定范围

- 默认只处理用户当前打开的笔记（`<current_note>`）。
- 用户说「母文件夹」「这个文件夹」「这一章的笔记」：处理该笔记所在的文件夹（不递归子文件夹，除非用户要求）。
- Bash 的 cwd 会漂移，而且安全 hook 不允许 `..` 或 vault 外的路径。每条命令开头先 `cd` 到 vault 根目录的绝对路径，然后用 vault 相对路径。

### 2. 跑扫描脚本

```bash
cd "<vault 绝对路径>" && python3 -I .claude/skills/note-polish/scripts/note_lint.py "<笔记或文件夹>" [...]
```

脚本只读不写，会按类别列出问题：

| 类别 | 含义 | 处理 |
|---|---|---|
| MARKED | 用户标记正下方的公式块 | 必须拆分，并删除标记行 |
| OVER | 估算宽度 ≥ 阈值（默认 66） | 拆分 |
| BORDERLINE | 宽度在 60–66 之间 | 不改，只在报告里列出 |
| TABLE | 表格行被 `\|` 打断、列数不一致、尾部空行 | 修复 |
| BALANCE | `$$` 未闭合、`\left`/`\right` 跨行、`\tag` 在 aligned 内部等 | 修复（多半是之前的编辑遗留） |
| STRAY_MARKER | 标记后面不是公式块 | 读上下文，弄不清楚就问用户 |

### 3. 校准阈值

宽度单位大约是一个字符宽，是估算值，不是像素。默认阈值 66 是在用户屏幕上校准的：他标记过的公式在 callout 内最窄约 69、在正文中约 74，没标记的可见公式最宽约 64。

- 笔记里有标记时，脚本会输出「标记块最窄宽度」。如果它低于 66，说明用户这次的窗口更窄，就用 `--threshold <该值>` 重跑一遍，按新阈值处理。
- 折叠的 callout（`> [!note]-`）里的公式用户平时看不到，所以不会去标记，但它们展开后一样会超出屏幕，同样要处理。
- 用户换了别的标记词时，用 `--marker '太长|TODO-split'` 这样的正则。

### 4. 读上下文，决定在哪里断行

逐个 Read 公式块及前后几行。断行规则见下一节。

### 5. 编辑

- 少量改动用 Edit 工具。
- 改动多（跨多个文件、十几处）时，用一段 `python3 -I - <<'EOF'` 脚本做精确字符串替换：先在内存里对每处断言 `count(old) == 1`，**全部通过后**再统一写回文件。要么全写，要么全不写，避免改到一半留下坏文件。
- 不要用 `sed` 改 LaTeX，反斜杠转义很容易出错。
- 这些笔记往往不在 git 里（先 `git status` 看一下）。导出目录（如 `~/Downloads`）对 hook 来说是只写的，`mkdir`/`cp` 备份会被拦截，所以别尝试，靠写前的全量断言保证安全。OneDrive 的版本历史是最后的退路，要在报告里说明。
- 如果文件在你读取之后被用户改过，以磁盘上的当前版本为准，重新读取，不要覆盖用户的修改。

### 6. 复查

重新跑一遍脚本。确认处理过的块已不再出现在 MARKED/OVER 中，且 BALANCE 没有新增问题。拆分后的每一行最好在 55 以内，留一点余量。

### 7. 报告（格式见文末）

## 公式分行规则

按优先级选择断点：

1. **链式等式** `a=b=c=d`：用 `aligned`，每个关系符一行，`&=` 对齐。断在关系符**之前**。
   ```latex
   \begin{aligned}
   v_{t+1}(s_t)&=v_t(s_t)-\alpha_t(s_t)\tilde g(v_t(s_t))\\
   &=v_t(s_t)-\alpha_t(s_t)\Big(v_t(s_t)-\big[r_{t+1}+\gamma v_\pi(s_{t+1})\big]\Big)
   \end{aligned} \tag{7.5}
   ```
2. **只有一个 `=`、右边很长**：断在顶层的 `+`/`-` 前，续行用 `&\quad+` 或 `&\qquad-`。可以断在 `\Big[ … \Big]` 里面，因为 `\big`/`\Big` 是独立的定界符：
   ```latex
   q_{t+1}(s_t,a_t)&=q_t(s_t,a_t)-\alpha_t(s_t,a_t)\Big[q_t(s_t,a_t)\\
   &\qquad-\big(r_{t+1}+\gamma r_{t+2}+\cdots\big)\Big]
   ```
3. **左边本身很长、只有一个 `=`**：用 `LHS={}&\text{第一段}\\ &+\text{第二段}`。`{}` 能让第二行的 `+` 保持二元运算符间距。
4. **并列的多个式子**（用 `,\quad` 或 `\qquad` 隔开）：用 `gathered`，断在分隔处，逗号保留在行尾。
5. **轨迹或箭头链**（`\xrightarrow`）：`s_1 &\xrightarrow…` 开头，续行以 `&\xrightarrow` 开头。
6. **尾部的条件或定义域**（`,\qquad s\in\mathcal S,\ j=0,1,\dots`）：单独放一行 `&\qquad s\in\mathcal S,\dots`。
7. **已经是 aligned 的块**：只在超长的那一行里加 `\\`，沿用原来的对齐列。

必须遵守的细节（违反会导致渲染报错或排版变形）：

- **`\tag{…}` 放在 `\end{aligned}` 之后**。MathJax 不允许 `\tag` 写在 aligned/gathered 内部。
- **`\left…\right` 不能跨 `\\`**。尽量断在它们外面；必须断在里面时，拆成 `\left( … \right.\\ \left. … \right)`，或换成同等大小的 `\Bigg(`/`\Bigg)`。改用 `\Bigg` 会改变括号尺寸，在报告里说明。
- **在 callout 里**，新增的每一行都要带上和原来完全相同的前缀（`> `、`> > `、列表缩进等）。漏掉前缀，公式就会掉出 callout。
- **正文引用**：如果下文写着「第二个等号来自…」「上式第一项…」，拆分后要核对这些说法仍然成立。
- 拆分后各行长度尽量均衡。不要把一个 `\underbrace` 拆开。
- 行内公式（`$…$`）不在这个 skill 的范围内，表格里的除外。

## 表格修复

Obsidian 把表格行里的每一个 `|` 都当作列分隔符，**包括 `$…$` 里面的**。

- 公式里的 `|` 按含义替换：绝对值或集合大小用 `\lvert x\rvert`，条件概率或“使得”用 `\mid`，范数用 `\lVert x\rVert`。注意 `\|` 本身也含 `|` 字符，同样会断列。
- wikilink 别名在表格里要写成 `[[note\|alias]]`。
- 修好之后删掉由错误分列产生的多余空列，以及末尾的空行，让每行列数与表头一致。
- 重写某张表时，单元格用紧凑写法 `| a | b |`，不要保留编辑器加的超长空格填充。只动出问题的那张表，别的表格保持原样。

## 用户标记

用户会在想拆的公式**正上方**单独写一行标记，默认是「长长长」。这行可能带 callout 前缀或缩进，比如 `>    长长长`。

- 被标记的公式无论估算宽度多少都要拆，然后**整行删除标记**。
- 删除标记时注意不要留下多余的空行，也不要吃掉原本就有的空行。

## 报告格式

```markdown
已把 N 处过长的公式分行，并修复了 M 处表格问题；只改了排版，没改任何内容。

**你标记的（N1 处）**
- [[笔记名]] Box 7.1：噪声观测 $\tilde g$，拆成 g 项与 η 项两行
- …

**额外发现的（N2 处）**
- [[笔记名]]：(2.5)，每个等号一行
- …

**接近阈值、没有改的**：[[笔记A]] 约 158 行附近、… 如果在你屏幕上也超出了，同样标「长长长」，我再拆。

**发现但没动的内容问题**（如有）：…

已核对 $$ 与 \begin/\end 配对，但没有在 Obsidian 里实际渲染检查。这些笔记不在 git 中，需要回退的话可以用 OneDrive 版本历史。
```

用公式所在的章节、Box 或公式编号来描述位置，用户在 Obsidian 里能直接找到，比单纯给行号更好用。
